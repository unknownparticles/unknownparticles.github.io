# Design

## Context

Astro 静态站，已有双语字典、主题、原生 CSS 和 Playwright。工作区初始干净，提交信息须为纯中文。OpenSpec 使用本机已安装的 CLI 初始化。

## Goals / Non-Goals

目标：用 JPEG 解析、Photo Lab 和本站三个可追溯案例突出图像与工程实践；文章示例正确；双语与移动端完整。
非目标：重建视觉系统、修改外部仓库、承诺未经测量的收益、编造职业经历或贡献记录。

## Decisions

1. 精选项目使用独立标记，避免截图存在性决定技术曝光；无截图项目使用与技术内容相关的文本流程。
2. 案例采用类型化双语数据和统一静态模板，复用项目源码地址，并为重要判断附证据链接。将已知实现与待验证的边界明确区分。
3. 首页顺序为定位、精选项目、精选阅读、能力介绍、最近文章，删除重复的几何能力区，降低数量徽章权重；保留现有交互几何形状及减少动画机制。
4. 修复文章的矩阵与滑动窗口示例，移除错误的 SIMD 优化和笼统性能断言。验证脚本直接提取文章中的 C++ 代码，编译并运行正确性检查，另提供可选基准模式。
5. 调整现有回归用例以匹配新信息结构；增加案例路由、语义阅读与语言切换检查，不用空洞快照替代行为测试。

## Risks / Trade-offs

公开项目源码可能包含实验性实现；案例不得把改进建议描述为已实现。外部仓库核验结果保存在验证记录中。保留现有品牌，局部降低装饰强度以避免无关的全面重设计。

## Validation

OpenSpec 严格校验、Astro 类型检查与构建、文章代码编译校验、现有浏览器回归；390/768/1440 截图查看首页与案例，并验证深色、英文、键盘链接和减少动画。

## 源码核验后的范围调整

ImageQualityAnalyzer 在核验版本中仅包含 README，没有可审查的实现，因此不入选首页，项目目录明确其说明性质。第三个精选改为本站，具备真实路由、内容校验、部署流程和浏览器测试，可直接追溯。

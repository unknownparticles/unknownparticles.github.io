> 修订于 2026-10-30：旧版把 XMP 与 EXIF 混为一谈，并使用固定文件偏移、缺少边界检查的示例。本次撤下这些示例，按文件结构重新整理解析路径。更完整的实现入口见 [JPEG 技术案例](/projects/jpeg-info/)。

读取 JPEG 的拍摄参数，可以从标记段和 TIFF 结构入手，不必先解码像素。难点在于正确确定数据所属的段、字节序与偏移基准。

## 先区分 JPEG、EXIF 和 XMP

JPEG 文件可以包含多个应用标记段。APP1 只是容器类型，不能直接把所有 APP1 内容当作 EXIF。

| 容器 | 常见标识 | 内容 |
| --- | --- | --- |
| APP0 | `JFIF` 后跟零字节 | 密度、版本等交换格式信息 |
| APP1 | `Exif` 后跟两个零字节 | TIFF 头与 IFD 目录 |
| APP1 | XMP 命名空间标识 | XML 元数据 |
| APP2 | `ICC_PROFILE` 后跟零字节 | 颜色配置文件分片 |

一张图可以同时包含这些数据。搜索到 `<?xpacket begin=` 说明可能找到了 XMP 包，不能据此称为 EXIF 解码；按空格截断 XML 也无法可靠确定元数据边界。

## 用段长度定位内容

下面是概念结构示意，各段是否出现、顺序和长度由实际文件决定：

```text
SOI
  APP0  → 可选 JFIF
  APP1  → 检查标识后识别 EXIF 或 XMP
  APP2  → 可选 ICC 分片
  其他标记段
SOS
  压缩扫描数据
EOI
```

对于带长度字段的段，长度以大端存储，包含长度字段自己的两个字节，不包含前面的两个标记字节。因此载荷长度为段长度减二。读取前应确认长度字段存在、段长度至少为二、载荷没有超过文件范围。

不能只在文件字节中搜索 `FF E1`，因为压缩数据或其他载荷里也可能出现相同字节。先按结构遍历段，遇到 APP1 再检查载荷标识，才能确定后续内容的含义。SOS 后的扫描数据还有字节填充、重启标记等规则，需要单独处理；读取头部元数据的示例不应被描述成完整图像解码器。

对应实现可查看 [jpeg_indexer.cpp](https://github.com/unknownparticles/jpeg-info/blob/90c7bbb78dc47462d52c090071c489bc7685084b/src/jpeg_indexer.cpp)。这个版本提供段索引和 APP 子类型识别，但 SOS 后的处理会结束索引，不能据此承诺完整支持多次扫描。

## TIFF 字节序与偏移基准

确认载荷以 EXIF 标识开头后，接下来的 TIFF 头才是解析基准：

1. 读取 `II` 或 `MM`，分别表示小端和大端。
2. 按该字节序验证 TIFF 标识值 42。
3. 读取首个 IFD 的偏移；这个偏移相对于 TIFF 头起点。
4. 从目录起点读取条目数量，再逐项处理。

JPEG 段长度的字节序与 TIFF 内部字节序是两个独立层次。不能因为文件含有 EXIF，就假定它从第十三个字节开始，也不能把所有 IFD 偏移当作文件绝对地址。APP0、其他 APP1 或不同长度的段都会改变 TIFF 在文件中的位置。

## IFD 条目：值可能就在条目里

经典 TIFF 的每个 IFD 条目由十二个字节构成：

| 字段 | 字节数 | 含义 |
| --- | --- | --- |
| Tag | 2 | 标签编号 |
| Type | 2 | 数据类型 |
| Count | 4 | 该类型元素的个数 |
| Value / Offset | 4 | 内联值或相对于 TIFF 头的数据偏移 |

解析时先由类型确定元素大小，再计算总数据长度。如果数据不超过四个字节，值就存放在最后四字节的字段中；更大的数据需要按偏移定位。类型、长度和字节序共同决定读取方式，不能把最后四字节一律解释为地址。

遍历 EXIF 与 GPS 等子目录时，同样需要保留 TIFF 基准，并限制访问范围。Count 与元素大小相乘、偏移与长度相加，都要先检查是否会溢出及是否仍在载荷内。对有理数类型，还要处理分母为零等异常情况。

项目中的实现入口是 [parse_exif.cpp](https://github.com/unknownparticles/jpeg-info/blob/90c7bbb78dc47462d52c090071c489bc7685084b/src/parse_exif.cpp)。阅读时可以沿着字节序读取、IFD 条目和标签格式化三个部分追踪，而不是从打印结果倒推文件结构。

## 如何验证解析结果

先准备知道内容的样本，再核对段偏移、标识、TIFF 起点与标签值。建议至少覆盖：

- EXIF 不在第一个应用段，以及同时存在 XMP 的图片。
- 大端与小端 TIFF、内联值与需要偏移读取的值。
- 没有 EXIF 的有效图片，以及段长度不足、目录超出载荷的异常输入。
- 元数据被编辑或剥离后的文件。

可以使用项目的 `--segments` 和 `--exif` 输出辅助定位，再用十六进制查看器核对原始字节。上面是验证方法，不代表这些样本已在本文中全部跑过；这个版本的构建、跨工具对照和异常输入回归仍需独立执行并记录结果。

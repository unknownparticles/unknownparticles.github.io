做相册时，图片缩放与左右翻页容易争夺触摸事件。先纠正一个前提：`ViewPager2` **继承 ViewGroup，内部使用 RecyclerView**，并不是 RecyclerView 的子类。图片只收到 DOWN、之后收到 CANCEL，通常应先检查父容器是否在 MOVE 阶段拦截。

## 1. 一个手势的生命周期

单指手势通常是 `ACTION_DOWN → 零个或多个 ACTION_MOVE → ACTION_UP`，或者以 `ACTION_CANCEL` 结束。CANCEL 与 UP 是两种终止路径，不是每次都先 CANCEL 再 UP。多指还包括 `ACTION_POINTER_DOWN / ACTION_POINTER_UP`，应使用 `getActionMasked()` 读取动作类型，并用 pointer ID 跟踪手指，不能把索引当成稳定身份。

## 2. 消费与拦截是两个概念

| 方法 | 所属对象 | 返回 true 的含义 |
| --- | --- | --- |
| `dispatchTouchEvent` | Activity、View 等 | 这次分发被处理；内部仍可能已分发到子 View |
| `onInterceptTouchEvent` | ViewGroup | 父容器接管，不再继续按原目标分发 |
| `onTouchEvent` | View 等 | 当前处理者消费事件 |

`dispatchTouchEvent()` 返回 false 表示当前分发没有处理，结果返回调用者，并不表示继续往子控件传递。普通 View 也没有可重写的 `onInterceptTouchEvent()`。

不要自行用一个遍历子 View 的循环替代框架分发：系统还要处理命中测试、绘制顺序、坐标变换、多指拆分、触摸目标记录和 CANCEL。私有的 `dispatchTransformedTouchEvent` 也不是应用层能直接调用的公开 API。

## 3. DOWN 决定后续目标

如果子 View 接受 DOWN，它通常成为当前手势的触摸目标，后续 MOVE／UP 沿这条路径分发。但父容器仍可能中途拦截；此时子 View 收到 CANCEL，随后事件转给父容器。

父容器即使不消费，仍可以在分发或拦截方法里观察事件，所以“子 View 消费 DOWN 后，父 ViewGroup 就看不到 MOVE”是不准确的。日志要写明观察的是哪个回调。

如果自定义 View 在 DOWN 返回 false，通常不会继续得到这个手势的后续事件；不能只在 MOVE 中才尝试接管。`OnTouchListener` 也受 View 是否启用及是否返回 true 等因素影响，监听器消费后可能不再调用该 View 的 `onTouchEvent`。

## 4. 请求父级不要拦截

`getParent().requestDisallowInterceptTouchEvent(true)` 是子 View 向父容器及祖先提出**不拦截当前序列**的请求，不是阻止父级所有回调，也不会自动让子 View 消费事件。新的 DOWN 开始时，框架会重置这一请求。

下面是可放进 `TouchProbeView.java` 的最小自定义 View。它从 DOWN 开始拥有手势、在移动超过 touch slop 后取消点击，并处理 UP／CANCEL 清理。它用于观察分发，不实现图片缩放或拖动。

```java
import android.content.Context;
import android.util.AttributeSet;
import android.view.MotionEvent;
import android.view.View;
import android.view.ViewConfiguration;

public class TouchProbeView extends View {
    private float downX, downY;
    private boolean moved;
    private final int touchSlop;

    public TouchProbeView(Context context, AttributeSet attrs) {
        super(context, attrs);
        touchSlop = ViewConfiguration.get(context).getScaledTouchSlop();
        setClickable(true);
    }

    @Override
    public boolean onTouchEvent(MotionEvent event) {
        switch (event.getActionMasked()) {
            case MotionEvent.ACTION_DOWN:
                downX = event.getX();
                downY = event.getY();
                moved = false;
                if (getParent() != null)
                    getParent().requestDisallowInterceptTouchEvent(true);
                return true;
            case MotionEvent.ACTION_MOVE:
                float dx = event.getX() - downX;
                float dy = event.getY() - downY;
                if (dx*dx + dy*dy > (float) touchSlop*touchSlop) moved = true;
                return true;
            case MotionEvent.ACTION_POINTER_DOWN:
                moved = true; // 多指交互不触发单击
                return true;
            case MotionEvent.ACTION_UP:
                if (getParent() != null)
                    getParent().requestDisallowInterceptTouchEvent(false);
                if (!moved) performClick();
                return true;
            case MotionEvent.ACTION_CANCEL:
                moved = false;
                if (getParent() != null)
                    getParent().requestDisallowInterceptTouchEvent(false);
                return true;
            default:
                return true;
        }
    }

    @Override
    public boolean performClick() {
        super.performClick();
        return true;
    }
}
```

## 5. ViewPager2 与缩放图片如何协作

如果产品交互要求缩放期间禁止翻页，可以通过 `ViewPager2.setUserInputEnabled(false)` 暂停用户滚动，并在交互结束时恢复原状态。这不会直接替你实现图片缩放，也不阻止程序主动调用翻页方法。

更细的策略是：图片在原始倍率时把翻页方向的拖动交给父级；图片放大或双指缩放时请求不拦截；图片拖到边缘后，按方向决定是否允许父级接管。切换必须在父级已经拦截之前完成，一旦子 View 收到 CANCEL，就应结束当前识别，不能期待后续 MOVE 自动回到它。

同向滚动容器嵌套还涉及 nested scrolling；仅在 DOWN 中设置一次不拦截，可能造成父级永远无法翻页，不能说这样就解决了所有冲突。

## 6. 如何排查

分别记录 DOWN、MOVE、UP、CANCEL 与各方法返回值，测试单击、拖动、双指、父级中途接管和系统取消。源码与规则以 [Android ViewGroup 触摸处理说明](https://developer.android.com/develop/ui/views/touch-and-input/gestures/viewgroup)及 [ViewPager2 API](https://developer.android.com/reference/androidx/viewpager2/widget/ViewPager2)为准。本文的流程图解释一般机制，不替代具体控件版本的行为验证。

### 2. 框架选择

目前主流的前端框架有：

#### React
```jsx
// React 函数组件示例
import React, { useState } from 'react';

function Counter() {
    const [count, setCount] = useState(0);
    
    return (
        <div>
            <p>Count: {count}</p>
            <button onClick={() => setCount(value => value + 1)}>
                Increment
            </button>
        </div>
    );
}
```

#### Vue.js
```vue
<!-- Vue 3 Composition API -->
<template>
    <div>
        <p>Count: {{ count }}</p>
        <button @click="increment">Increment</button>
    </div>
</template>

<script>
import { ref } from 'vue';

export default {
    setup() {
        const count = ref(0);
        
        const increment = () => {
            count.value++;
        };
        
        return {
            count,
            increment
        };
    }
};
</script>
```

## 状态管理

### 1. React 状态管理

#### Redux Toolkit

新代码使用 Redux Toolkit；以下 store 仍需通过 React-Redux Provider 接入组件。
```javascript
// store.js
import { configureStore, createSlice } from '@reduxjs/toolkit';

const counter = createSlice({
    name: 'counter',
    initialState: { count: 0 },
    reducers: {
        increment(state) { state.count += 1; }
    }
});
export const { increment } = counter.actions;
export const store = configureStore({ reducer: { counter: counter.reducer } });
```

#### Context API
```jsx
// UserContext.js
import React, { createContext, useContext, useState } from 'react';

const UserContext = createContext();

export function useUser() {
    return useContext(UserContext);
}

export function UserProvider({ children }) {
    const [user, setUser] = useState(null);
    
    return (
        <UserContext.Provider value={{ user, setUser }}>
            {children}
        </UserContext.Provider>
    );
}
```

### 2. Vue 状态管理

#### Pinia (Vue 3)
```javascript
// stores/user.js
import { defineStore } from 'pinia';

export const useUserStore = defineStore('user', {
    state: () => ({
        user: null,
        isLoggedIn: false
    }),
    actions: {
        setUser(userData) {
            this.user = userData;
            this.isLoggedIn = true;
        },
        logout() {
            this.user = null;
            this.isLoggedIn = false;
        }
    }
});
```

## 路由管理

### React Router

使用 history 路由的 SPA 需要宿主把未知应用路径回退到入口 HTML；纯静态托管没有这个能力时，可考虑 hash 路由。
```jsx
// App.js
import { BrowserRouter, Routes, Route } from 'react-router-dom';
import Home from './pages/Home';
import About from './pages/About';

function App() {
    return (
        <BrowserRouter>
            <Routes>
                <Route path="/" element={<Home />} />
                <Route path="/about" element={<About />} />
            </Routes>
        </BrowserRouter>
    );
}
```

### Vue Router
```javascript
// router/index.js
import { createRouter, createWebHistory } from 'vue-router';
import Home from '../views/Home.vue';

const routes = [
    { path: '/', component: Home },
    { path: '/about', component: About }
];

export const router = createRouter({
    history: createWebHistory(),
    routes
});
```

## API 交互

### 1. Fetch API

Fetch 遇到 HTTP 404／500 不会自动 reject；必须检查 `response.ok`。此例把错误继续抛给调用方，由界面呈现错误与重试状态。
```javascript
// 使用 Fetch API
async function fetchData() {
    try {
        const response = await fetch('/api/data');
        if (!response.ok) throw new Error(`HTTP ${response.status}`);
        const data = await response.json();
        return data;
    } catch (error) {
        console.error('Error:', error);
        throw error;
    }
}
```

### 2. Axios
```javascript
// 使用 Axios
import axios from 'axios';

const api = axios.create({
    baseURL: 'https://api.example.com',
    timeout: 10000
});

// 请求拦截器
api.interceptors.request.use(config => {
    // 添加认证 token
    const token = localStorage.getItem('token');
    if (token) {
        config.headers.Authorization = `Bearer ${token}`;
    }
    return config;
});
```

### 3. 缓存策略

以下只演示安装期预缓存，尚未实现 `fetch` 读取缓存、旧缓存清理与更新策略，因此不能单凭此段声称离线可用。资源路径必须换成真实构建产物；带哈希的文件名不宜手写。
```javascript
// Service Worker 缓存
const CACHE_NAME = 'my-app-cache-v1';
const urlsToCache = [
    '/',
    '/static/js/bundle.js',
    '/static/css/main.css'
];

self.addEventListener('install', event => {
    event.waitUntil(
        caches.open(CACHE_NAME)
            .then(cache => cache.addAll(urlsToCache))
    );
});
```

## 部署策略

### 1. 静态网站托管
静态站点需要把构建产物交给部署任务，不能假设前一任务的工作目录自动共享。可使用本站的 [部署工作流](https://github.com/unknownparticles/unknownparticles.github.io/blob/master/.github/workflows/deploy.yml)作为具体项目示例，或参考下一篇 [开源项目实践](/2025/11/11/开源项目实践/)中的完整 Pages 构建与部署配置。

项目的 Node.js 版本应与 `engines` 和锁文件匹配；不要复制已结束维护的 Node 16 环境。Actions 的触发分支也要与实际仓库一致，本站是 `master`。

### 2. Docker 部署
```dockerfile
# 面向产出 dist/ 的纯静态前端，假设仓库已有 package-lock.json。
FROM node:24-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM nginx:stable-alpine
COPY --from=build /app/dist /usr/share/nginx/html
EXPOSE 80
```

构建上下文应通过 `.dockerignore` 排除 `node_modules`、`dist`、`.git` 与本地秘密文件。上述 Nginx 示例适用于静态文件，history 路由 SPA 需额外配置 fallback，SSR 服务需使用对应服务端产物。

一张全景图摊在平面上，往往是又长又宽的一幅图片；放进全景查看器后，却像站在原地转头看四周。图片没有变，变化的是我们从中取颜色的方式：屏幕上的每个位置先对应一个观察方向，再由方向找到环境图里的颜色。

理解了这一步，就不必一开始纠结“应该画一个球还是一个立方体”。网格只是承载显示的一种办法，真正决定画面的是方向如何生成、方向怎样映射到纹理，以及上传图片时使用了什么坐标约定。

本文比较**等距柱状投影二维图（equirectangular）**与**六面立方体纹理（cubemap）**。两者都可以用全屏三角形显示，不必实际创建球体或立方体网格。`envIrradiance` 常用于估算漫反射环境光，并非直接显示全景背景所必需。

## 1. 从屏幕坐标得到观察方向

![屏幕射线分别映射到经纬二维纹理和立方体六面](/img/posts/panorama/direction-mapping.svg)

下面两个片段着色器使用 GLSL ES 1.00，可用于 OpenGL ES 2.0 / WebGL 1。宿主需绘制覆盖视口的三角形，并设置以下 uniform：

| 参数 | 含义 |
| --- | --- |
| `iResolution` | 实际帧缓冲尺寸，两个分量都必须大于零 |
| `iFov` | **垂直**视场角，单位为度，建议限定在 1～179 度 |
| `iYawPitch` | 水平与俯仰角，单位为弧度 |
| `environmentMap` | 绑定到对应纹理单元的环境纹理 |

射线为 `normalize(vec3(pixel.x*aspect*tan(fov/2), pixel.y*tan(fov/2), -1))`。这里相机朝向负 Z，Y 向上，必须统一垂直／水平 FOV 的定义。窗口纵横比改变时，不应把垂直 FOV 再除以 aspect。

### 先确定中央这条射线

先看视口中心：`pixel` 接近 `(0,0)`，在没有旋转时，方向就是负 Z。再把视线移向屏幕右侧，射线的 X 分量增加；向上看则是 Y 分量增加。这种检查很简单，却能迅速发现左右颠倒或坐标原点混用的问题。

视场角决定相同屏幕位置偏离中央方向多少。垂直 FOV 变大，上下边缘的射线展开得更开，画面能装下更多环境；宽高比负责把同样的规则扩展到水平方向。这里只是改变投影，不会凭空增加原图细节。

代码先应用俯仰，再应用水平旋转。三维旋转通常与顺序有关，所以接入鼠标或触摸操作时，要先选定一套约定，再用固定朝向检查。若随手把两段旋转交换，结果可能还能显示，但操作方向会变得难以解释。

## 2. 等距柱状投影纹理

等距柱状图通常宽高比为 2:1，横向表示经度，纵向表示纬度。方向归一化后，通过 `atan(z,x)` 求经度，通过 `acos(y)` 求从北极量起的夹角。它属于球面参数化，但不要与其他形式的 sphere map 混为一谈。

```glsl
#version 100
#ifdef GL_FRAGMENT_PRECISION_HIGH
precision highp float;
#else
precision mediump float;
#endif
uniform vec2 iResolution;
uniform float iFov;
uniform vec2 iYawPitch;
uniform sampler2D environmentMap;

vec3 viewDirection() {
    vec2 pixel = 2.0*gl_FragCoord.xy/iResolution - 1.0;
    float t = tan(radians(clamp(iFov, 1.0, 179.0))*0.5);
    vec3 d = normalize(vec3(pixel.x*iResolution.x/iResolution.y*t, pixel.y*t, -1.0));
    float cp = cos(iYawPitch.y), sp = sin(iYawPitch.y);
    d = vec3(d.x, cp*d.y-sp*d.z, sp*d.y+cp*d.z);
    float cy = cos(iYawPitch.x), sy = sin(iYawPitch.x);
    return vec3(cy*d.x+sy*d.z, d.y, -sy*d.x+cy*d.z);
}
void main() {
    vec3 d = normalize(viewDirection());
    float u = atan(d.z, d.x)/(2.0*3.14159265) + 0.5;
    float v = acos(clamp(d.y, -1.0, 1.0))/3.14159265;
    gl_FragColor = vec4(texture2D(environmentMap, vec2(u,v)).rgb, 1.0);
}
```

本例让北极对应 `v=0`，南极对应 `v=1`。宿主上传纹理时应使第一行与北极行一致；若图像加载器翻转了 Y 轴，需统一翻转约定，而非同时在上传和 shader 两处翻转。经度零点也应与图片约定一致，可用已知方向标记验证。

等距柱状图在两极处拉伸明显。横向接缝需要环绕采样；ES 2.0 非二次幂二维纹理使用 `REPEAT` 有限制，不能无条件设置。可使用合适的二次幂尺寸，或根据平台能力处理接缝。

### 如何看懂经纬度映射

可以把二维纹理想成把地球仪沿一条经线剪开后展开。横向走一圈回到起点，纵向从北极走到南极。`atan` 提供水平方向上的角度，`acos` 提供从北向南的位置，再把角度范围压到纹理坐标的零到一之间。

这也解释了接缝为什么集中在左右边缘：纹理坐标接近零和接近一的位置，在三维方向上其实互相挨着。如果边缘颜色不一致，或者过滤跨边缘的方式不匹配，转头时就会看到一条竖线。排查时先对照原图两侧，再检查上传方向和采样设置，别急着修改整个投影公式。

极点附近则是另一种问题。很多经度都汇聚到相近方向，展开图却仍给它们分配了横向空间，因此顶端和底端看起来被拉长。这是表示方式带来的采样分布，不是单纯的 shader 算错。

## 3. 立方体纹理：真正使用 samplerCube

Cubemap 由 +X、-X、+Y、-Y、+Z、-Z 六个正方形面组成。采样器按方向选面及面内坐标；面朝向由 API 约定，不是随意拼接六张图片。旧版这一节误复制了二维采样代码，实际上没有使用 cubemap。

![立方体六面方向与面内坐标示意](/img/posts/panorama/cubemap-faces.svg)

```glsl
#version 100
#ifdef GL_FRAGMENT_PRECISION_HIGH
precision highp float;
#else
precision mediump float;
#endif
uniform vec2 iResolution;
uniform float iFov;
uniform vec2 iYawPitch;
uniform samplerCube environmentMap;

vec3 viewDirection() {
    vec2 pixel = 2.0*gl_FragCoord.xy/iResolution - 1.0;
    float t = tan(radians(clamp(iFov, 1.0, 179.0))*0.5);
    vec3 d = normalize(vec3(pixel.x*iResolution.x/iResolution.y*t, pixel.y*t, -1.0));
    float cp = cos(iYawPitch.y), sp = sin(iYawPitch.y);
    d = vec3(d.x, cp*d.y-sp*d.z, sp*d.y+cp*d.z);
    float cy = cos(iYawPitch.x), sy = sin(iYawPitch.x);
    return vec3(cy*d.x+sy*d.z, d.y, -sy*d.x+cy*d.z);
}
void main() {
    gl_FragColor = vec4(textureCube(environmentMap, viewDirection()).rgb, 1.0);
}
```

这里才是两种表示的主要区别：二维图需要算 UV，cubemap 直接传入三维方向。GLSL ES 1.00 片段着色器中 `texture2D` 的第三个参数是 **LOD bias**，不是明确指定 mip 层的 `textureLod`。本例移除了这个容易误读的参数，也不依赖显式 LOD 扩展。

## 4. 上传 cubemap 的注意事项

下面是已有 OpenGL 上下文中的 C++ 片段，使用 stb_image 解码。六张图片必须具有一致的正方形尺寸。数组顺序对应枚举从 `GL_TEXTURE_CUBE_MAP_POSITIVE_X` 连续递增的顺序；本例称 -Z 为前方，以匹配相机朝向，资源命名需自行核对。

```cpp
#include <array>
#include <stdexcept>
#include <vector>
// 需另行包含平台 OpenGL 函数加载器和 stb_image.h。

GLuint loadCubemap(const std::array<const char*, 6>& paths) {
    std::array<std::vector<unsigned char>, 6> pixels;
    int size = 0;
    // 先完成所有解码与校验，再创建 GPU 纹理。
    for (int i = 0; i < 6; ++i) {
        int w = 0, h = 0, channels = 0;
        auto* data = stbi_load(paths[i], &w, &h, &channels, 3);
        if (!data) throw std::runtime_error("cubemap 图片读取失败");
        if (w <= 0 || w != h || (i != 0 && w != size)) {
            stbi_image_free(data);
            throw std::runtime_error("六个面必须为同尺寸正方形");
        }
        size = w;
        pixels[i].assign(data, data + static_cast<std::size_t>(w)*h*3);
        stbi_image_free(data);
    }
    GLint previousAlignment = 4;
    glGetIntegerv(GL_UNPACK_ALIGNMENT, &previousAlignment);
    glPixelStorei(GL_UNPACK_ALIGNMENT, 1); // RGB 行字节数不一定是四的倍数
    GLuint texture = 0;
    glGenTextures(1, &texture);
    glBindTexture(GL_TEXTURE_CUBE_MAP, texture);
    for (int i = 0; i < 6; ++i)
        glTexImage2D(GL_TEXTURE_CUBE_MAP_POSITIVE_X+i, 0, GL_RGB,
                     size, size, 0, GL_RGB, GL_UNSIGNED_BYTE, pixels[i].data());
    glTexParameteri(GL_TEXTURE_CUBE_MAP, GL_TEXTURE_MIN_FILTER, GL_LINEAR);
    glTexParameteri(GL_TEXTURE_CUBE_MAP, GL_TEXTURE_MAG_FILTER, GL_LINEAR);
    glTexParameteri(GL_TEXTURE_CUBE_MAP, GL_TEXTURE_WRAP_S, GL_CLAMP_TO_EDGE);
    glTexParameteri(GL_TEXTURE_CUBE_MAP, GL_TEXTURE_WRAP_T, GL_CLAMP_TO_EDGE);
    // ES 2.0 没有核心 GL_TEXTURE_WRAP_R，不在本例中调用。
    glPixelStorei(GL_UNPACK_ALIGNMENT, previousAlignment);
    return texture;
}
```

调用前确认尺寸未超过 `GL_MAX_CUBE_MAP_TEXTURE_SIZE`，并统一 stb_image 的垂直翻转设置。宿主负责检查 GPU 分配错误、恢复需要保留的绑定状态，以及在合适的上下文中删除纹理。上述代码是 RGB 八位输入；真正的浮点 HDR 图需使用 `stbi_loadf` 及平台支持的浮点纹理格式，显示前还需曝光、色调映射与输出编码。

### 六张图片怎样拼成同一个空间

Cubemap 不再把方向换算成经纬二维坐标，而是把三维方向直接交给 `samplerCube`。纹理采样会根据方向选择面，并确定面内位置。不过，“自动选面”不意味着六张随便摆放的图片也能正确拼接：每张图代表哪个轴向、上方朝哪里，仍要由资源准备与上传约定保证。

第一次调试时，复杂的街景或室内全景反而不容易看出错误。给六个面写上方向名称，再画出向上的箭头，就能区分“面放错了”和“同一张面旋转了”。只交换文件顺序可能暂时修好正面，却把天顶和地面弄反，所以每次都应一起检查六个方向。

上传代码先检查六张图片的大小，再创建纹理，是为了避免处理中途才发现某一面不是正方形。行对齐也容易被忽略：RGB 每像素三个字节，当一行的字节数不是默认对齐的整数倍时，读错行起点就可能得到倾斜或错位的图案。这种现象应先检查数据布局，而不是归咎于球面投影。

## 5. 如何选型与验证

两种表示都可以描述同一个环境。Cubemap 并非天然更真实，性能与内存也不能只按“一张”或“六张”判断：同样每通道字节数下，二维图占用约为 `W*H` 个像素，cubemap 为 `6*S*S` 个像素，还需计入 mipmap。

先用标有轴向的测试图验证 +X、-X、+Y、-Y、+Z、-Z，再检查接缝、极点和窗口比例变化。图中的方向示意不冒充真实场景渲染结果。平台 API 的精确定义可参考 [OpenGL ES 2.0 规范](https://registry.khronos.org/OpenGL/specs/es/2.0/es_full_spec_2.0.pdf)。

本文按上下文、着色器、缓冲区、纹理与绘制顺序整理 OpenGL 入门。代码片段统一采用 **桌面 OpenGL 3.3 Core / GLSL 330**；需要先创建匹配的上下文，并加载对应 OpenGL 函数。GLFW、Qt 与 OpenGL ES 的上下文创建方式不同，不能把它们的代码不加区分地拼在一起。

## 1. 上下文与状态机

OpenGL 是图形 API，驱动实现其行为。上下文保存绑定对象、测试开关、混合参数等状态。调用需要上下文的指令前，必须在当前线程将对应上下文设为 current。

一个上下文不能同时在多个线程 current，但可以解除绑定后转移到另一线程。上下文也不是由函数调用栈决定：函数 a 调用函数 b，不会自动创建或切换上下文。多个上下文能否共享资源取决于创建时的共享设置，并非所有对象类型都可共享。

“状态机”可以理解为：先设置状态，再让绘制命令使用当前状态。例如 `glEnable(GL_DEPTH_TEST)` 修改开关；`glDrawElements(GL_TRIANGLES, ...)` 按指定图元类型和绑定资源提交绘制。并不是某个全局“画线状态”会自动改变所有绘制调用的图元类型。

## 2. 初始化、视口与深度

设置清屏颜色与视口是常见初始化步骤。视口使用帧缓冲像素尺寸，在高 DPI 窗口中不一定等于逻辑尺寸；窗口变化时应更新视口。`glGetIntegerv(GL_VIEWPORT, ...)` 读到的是**当前设置**，不是自动测得的真实窗口尺寸。

```cpp
glViewport(0, 0, framebufferWidth, framebufferHeight);
glClearColor(0.1f, 0.1f, 0.1f, 1.0f);
glEnable(GL_DEPTH_TEST);
// 每帧清空颜色和深度；需要先确保目标具有深度附件。
glClear(GL_COLOR_BUFFER_BIT | GL_DEPTH_BUFFER_BIT);
```

纯二维覆盖绘制可以关闭深度测试。开启测试不会凭空创建深度缓冲，也不能代替每帧清空深度。

在 Qt `QOpenGLWidget` 中，通常在 `initializeGL()` 初始化资源，`resizeGL()` 处理大小变化，`paintGL()` 绘制；`update()` 请求后续重绘，不等于立即同步执行绘制。应使用匹配版本的函数封装，例如 `QOpenGLFunctions_3_3_Core`，不能假设基础 ES 2.0 风格封装就拥有全部 VAO API。

## 3. 顶点与片段着色器

最简单的纹理渲染需要顶点与片段着色器。可编程管线还可以包括其他阶段，但支持情况取决于版本及扩展。Mesh Shader 等扩展的硬件要求，不能用来推导普通顶点／片段着色器应该选择什么 GLSL 版本。

顶点着色器输出裁剪空间位置，光栅化后其输出通常被插值为片段输入。片段不是“与屏幕像素一一对应的内存对象”：遮挡、过度绘制、MSAA、丢弃和提前测试都会影响执行及最终写入。

```glsl
#version 330 core
layout(location = 0) in vec2 position;
layout(location = 1) in vec2 texCoord;
out vec2 fragTexCoord;
void main() {
    gl_Position = vec4(position, 0.0, 1.0);
    fragTexCoord = texCoord;
}
```

```glsl
#version 330 core
in vec2 fragTexCoord;
uniform sampler2D textureSampler;
out vec4 outColor;
void main() {
    outColor = texture(textureSampler, fragTexCoord);
}
```

`gl_Position` 是内置输出，不是输入顶点属性。`sampler2D` uniform 保存纹理单元索引，纹理对象需要在宿主代码里绑定。旧式 `attribute/varying/texture2D/gl_FragColor` 属于不同 GLSL 版本的写法，不能直接放进 330 Core 示例。

### 编译与链接必须检查

下面代码假设已包含 OpenGL 加载器头文件及 `<stdexcept>`、`<vector>`。错误时抛出日志，避免继续使用链接失败的程序。

```cpp
GLuint compileShader(GLenum type, const char* source) {
    GLuint shader = glCreateShader(type);
    glShaderSource(shader, 1, &source, nullptr);
    glCompileShader(shader);
    GLint ok = GL_FALSE;
    glGetShaderiv(shader, GL_COMPILE_STATUS, &ok);
    if (!ok) {
        GLint size = 0;
        glGetShaderiv(shader, GL_INFO_LOG_LENGTH, &size);
        std::vector<char> log(size > 0 ? size : 1, '\0');
        glGetShaderInfoLog(shader, static_cast<GLsizei>(log.size()), nullptr, log.data());
        glDeleteShader(shader);
        throw std::runtime_error(log.data());
    }
    return shader;
}

GLuint createProgram(const char* vertexSource, const char* fragmentSource) {
    GLuint vertex = compileShader(GL_VERTEX_SHADER, vertexSource);
    GLuint fragment = 0;
    try {
        fragment = compileShader(GL_FRAGMENT_SHADER, fragmentSource);
    } catch (...) {
        glDeleteShader(vertex);
        throw;
    }
    GLuint program = glCreateProgram();
    glAttachShader(program, vertex);
    glAttachShader(program, fragment);
    glLinkProgram(program);
    glDeleteShader(vertex);
    glDeleteShader(fragment);
    GLint ok = GL_FALSE;
    glGetProgramiv(program, GL_LINK_STATUS, &ok);
    if (!ok) {
        GLint size = 0;
        glGetProgramiv(program, GL_INFO_LOG_LENGTH, &size);
        std::vector<char> log(size > 0 ? size : 1, '\0');
        glGetProgramInfoLog(program, static_cast<GLsizei>(log.size()), nullptr, log.data());
        glDeleteProgram(program);
        throw std::runtime_error(log.data());
    }
    return program;
}
```

## 4. VAO、VBO 与 EBO

- **VBO** 保存顶点属性字节数据。
- **VAO** 保存属性格式、启用状态及属性所引用的缓冲区等状态；它不复制顶点数据。
- **EBO** 保存索引数据；`GL_ELEMENT_ARRAY_BUFFER` 的绑定由当前 VAO 记录。

![VAO 引用顶点缓冲与索引缓冲，以及共享顶点的绘制方式](/img/posts/opengl-basics/buffer-relationships.svg)

调用 `glVertexAttribPointer` 时，当前 `GL_ARRAY_BUFFER` 的绑定会被记录到对应属性中。之后解绑 `GL_ARRAY_BUFFER` 不会抹掉这个引用。相反，在 VAO 仍绑定时解绑 `GL_ELEMENT_ARRAY_BUFFER`，会改变该 VAO 的 EBO 状态。

下面片段建立一个带 UV 的矩形，用四个顶点与六个索引画两个三角形。VAO 本身不能让六个独立顶点自动变成三个；共享边上的完整顶点属性一致时，索引才可以复用同一个顶点。

```cpp
const GLfloat vertices[] = {
    // position      UV
    -0.5f, -0.5f,    0.0f, 0.0f,
     0.5f, -0.5f,    1.0f, 0.0f,
     0.5f,  0.5f,    1.0f, 1.0f,
    -0.5f,  0.5f,    0.0f, 1.0f
};
const GLuint indices[] = {0, 1, 2, 0, 2, 3};
GLuint vao = 0, vbo = 0, ebo = 0;
glGenVertexArrays(1, &vao);
glGenBuffers(1, &vbo);
glGenBuffers(1, &ebo);
glBindVertexArray(vao);
glBindBuffer(GL_ARRAY_BUFFER, vbo);
glBufferData(GL_ARRAY_BUFFER, sizeof(vertices), vertices, GL_STATIC_DRAW);
glBindBuffer(GL_ELEMENT_ARRAY_BUFFER, ebo);
glBufferData(GL_ELEMENT_ARRAY_BUFFER, sizeof(indices), indices, GL_STATIC_DRAW);
glVertexAttribPointer(0, 2, GL_FLOAT, GL_FALSE, 4*sizeof(GLfloat), nullptr);
glEnableVertexAttribArray(0);
glVertexAttribPointer(1, 2, GL_FLOAT, GL_FALSE, 4*sizeof(GLfloat),
                      reinterpret_cast<void*>(2*sizeof(GLfloat)));
glEnableVertexAttribArray(1);
glBindVertexArray(0);
glBindBuffer(GL_ARRAY_BUFFER, 0);
```

一个索引同时选择位置、UV、颜色等所有启用属性的同号元素，不能给位置和颜色分别传两套索引。UV 接缝或不同法线可能要求复制位置相同的顶点。

## 5. 纹理数据与颜色空间

创建纹理后设置环绕与过滤方式，再上传像素。以下假设输入是紧密排列的 RGBA 八位像素，`width/height` 为正。像素格式 RGBA 与工作颜色空间是不同概念；转成 RGBA32 不代表完成色彩空间转换。

```cpp
GLuint texture = 0;
glGenTextures(1, &texture);
glActiveTexture(GL_TEXTURE0);
glBindTexture(GL_TEXTURE_2D, texture);
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_WRAP_S, GL_CLAMP_TO_EDGE);
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_WRAP_T, GL_CLAMP_TO_EDGE);
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_MIN_FILTER, GL_LINEAR);
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_MAG_FILTER, GL_LINEAR);
glTexImage2D(GL_TEXTURE_2D, 0, GL_RGBA8, width, height, 0,
             GL_RGBA, GL_UNSIGNED_BYTE, rgbaPixels);
```

本例不使用 mipmap，因而最小过滤选 `GL_LINEAR`。若改成 mipmap 过滤，需要补齐 mip 层。图像的上下方向、行跨度、BGR/RGB 顺序与 `GL_UNPACK_ALIGNMENT` 也需要匹配。对 sRGB 图片做线性光运算时，应另外规划 sRGB 纹理格式、采样解码及帧缓冲编码。

## 6. 绘制与释放

以下片段假设 `program` 已由上面的 shader 链接，纹理、VAO 均已准备好。

```cpp
glClear(GL_COLOR_BUFFER_BIT | GL_DEPTH_BUFFER_BIT);
glUseProgram(program);
glActiveTexture(GL_TEXTURE0);
glBindTexture(GL_TEXTURE_2D, texture);
glUniform1i(glGetUniformLocation(program, "textureSampler"), 0);
glBindVertexArray(vao);
glDrawElements(GL_TRIANGLES, 6, GL_UNSIGNED_INT, nullptr);
glBindVertexArray(0);
// 宿主随后交换缓冲；Qt QOpenGLWidget 管理自己的合成与交换。
```

`glDrawArrays(mode, first, count)` 使用顶点序列；`glDrawElements(mode, count, type, indices)` 有**四个参数**，count 是索引个数，不是去重后的顶点数。Core 模式绑定 EBO 后，最后一个参数是该缓冲区内的**字节偏移**，不是额外的“第五个偏移量”。`GL_UNSIGNED_BYTE/SHORT/INT` 必须与索引数据类型一致，索引不应存成浮点数。

`GL_TRIANGLES` 每三个顶点组成一个三角形；strip 和 fan 适用于不同的共享拓扑。`GL_QUADS`、`GL_QUAD_STRIP`、`GL_POLYGON` 不属于本文的 3.3 Core，矩形应拆成三角形。

不再使用资源时，在有效且匹配的 current 上下文中调用 `glDeleteTextures`、`glDeleteBuffers`、`glDeleteVertexArrays` 与 `glDeleteProgram`，释放每个创建的对象。不能遗漏额外的颜色 VBO，也不能在上下文已销毁后才释放。

## 7. FBO 与离屏渲染

FBO 组织颜色、深度、模板等附件，本身不是一块必然存储像素的“图片”。将纹理或 renderbuffer 作为附件，检查 `glCheckFramebufferStatus`，即可把绘制结果写入离屏目标；采样时不能读取正在作为同一绘制目标写入的纹理。

在 Qt 中，屏幕显示也可能经由 `QOpenGLWidget` 自己的 FBO 合成，默认目标不保证是 0。需要恢复时使用 `defaultFramebufferObject()`，并注意尺寸变化会影响其有效性。普通查询绑定可使用 `GLint binding; glGetIntegerv(GL_FRAMEBUFFER_BINDING, &binding);`，不必把 `GLuint*` 强转成 `GLint*`。
